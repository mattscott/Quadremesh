# 02 — Phase roadmap

Each phase lists **tasks**, **deliverables**, and **acceptance tests**. A phase is "done" only when
its acceptance tests pass on the shared corpus (`tests/corpus/`). Effort is rough relative sizing,
not calendar time.

---

## P0 — Scaffold  *(effort: S)*

**Tasks**
- Create `Quadremesh.sln`, the three `src/` projects + `tests/` project (.NET 8).
- CI: build + test on push (GitHub Actions, Windows + Linux).
- Coding standards, `.editorconfig`, analyzers, MIT/BSD license file + NOTICE attributing
  Instant Meshes/QuadriFlow papers & code influence.
- **Reference-oracle harness** (offline, dev/CI only — see
  [06 §6.6](../Docs/06-csharp-portability-analysis.md#66-reference-oracle-for-testing-build-im--quadriflow-locally)):
  scripts to build Instant Meshes + QuadriFlow (BSD/MIT) from source at pinned commits, drive them
  deterministically over corpus inputs, and emit golden outputs (quad mesh + fields/singularities
  where available) into `tests/golden/`. Not shipped, not linked into the managed artifact; goldens
  regenerated by explicit script, not every CI run. (Stub now; goldens populated per stage as P3+
  stabilize.)

**Deliverables**: empty-but-building solution; green CI; reference-oracle build script in place.
**Acceptance**: `dotnet build` + `dotnet test` pass with a placeholder test; the oracle script
builds IM/QuadriFlow and produces a golden for at least one corpus mesh.

---

## P1 — Mesh & IO  *(effort: M)*

**Tasks**
- `TriangleMesh` / `QuadMesh` POCOs.
- `HalfEdgeMesh`: index-based SoA connectivity; circulators; per-vertex normals, areas, cotangent
  weights; non-manifold-tolerant build; validation.
- `Quadremesh.IO`: OBJ reader/writer (tris+quads). (PLY/STL later.)
- Assemble the **test corpus** (sphere, torus, cylinder, scanned head, hard-surface part,
  non-manifold mess).

**Deliverables**: load OBJ → half-edge → save OBJ round-trips; corpus committed.
**Acceptance**: round-trip preserves topology on manifold inputs; non-manifold inputs load without
throwing (defects flagged, not fatal); adjacency/normal unit tests pass.

---

## P2 — Isotropic remesh pre-pass  *(effort: M)*

**Tasks**
- `IsotropicRemesher`: split long edges, collapse short edges, flip to improve valence, tangential
  relaxation (project back to original surface via `KdTree`/`BVH`).
- Target edge length from `TargetEdgeLength` or derived from `TargetQuadCount` + surface area.

**Deliverables**: near-uniform triangle mesh at requested resolution.
**Acceptance**: output edge-length histogram within tolerance of target; surface deviation below
threshold (Hausdorff sample); no inverted/degenerate triangles; runs on full corpus.

---

## P3 — Orientation field (4-RoSy)  *(effort: L — core)*

**Tasks**
- Tangent frames per vertex.
- `MultiresHierarchy.Build` (greedy edge-matching coarsening) — shared with P4.
- `OrientationFieldSolver`: closest-representative comparison; local Gauss–Seidel update;
  coarse→fine prolongation; red-black parallel sweeps.
- Singularity detection (rotation index per vertex).
- Debug export: per-vertex cross visualized as OBJ line segments / colored field.

**Deliverables**: smooth 4-RoSy field; singularity map.
**Acceptance**: on sphere/torus the field is smooth with expected singularity structure (e.g. torus
≈ 0 singularities; sphere has the topologically-required ones); field energy decreases monotonically
across hierarchy levels; **visual + singularity-count match to reference Instant Meshes** on 2–3
corpus meshes within tolerance.

---

## P4 — Position field (4-PoSy)  *(effort: L — core)*

**Tasks**
- `PositionFieldSolver`: lattice-representative snapping; local update; same hierarchy, coarse→fine.
- `SizingField` (uniform first; curvature-driven `ℓ_i` behind `AdaptiveSizing`).
- Debug export: anchors / lattice visualization.

**Deliverables**: converged position field consistent with the orientation field.
**Acceptance**: anchors form a coherent lattice (visual); neighboring anchors differ by ~integer
lattice steps (residual metric below threshold); converges on full corpus without NaNs.

---

## P5 — Extraction: quad-dominant  *(effort: L — #1 risk)* → **M4 demoable**

**Tasks**
- `LatticeExtractor`: union-find vertex collapse by lattice cell; edge building from integer offsets;
  face tracing (prefer 4-cycles; allow 3/5 near singularities).
- Post-process: remove doublets/valence-2, collapse degenerate edges, fill tiny holes, consistent
  reorientation, project output verts to original surface.

**Deliverables**: **end-to-end** TriangleMesh → quad-dominant QuadMesh.
**Acceptance**: output is manifold and watertight where input was; ≥ ~85% quads on smooth corpus
meshes; visually correct edge flow; no self-intersections introduced; runs full corpus without crash.

---

## P6 — Extraction: pure quad (QuadriFlow)  *(effort: L)* → **M5 production quality**

**Tasks**
- `IntegerSolver`: linear consistency constraints on edge integer jumps; **min-cost network flow**
  (managed network-simplex / SSP) to choose globally consistent offsets; local boolean SAT for
  T-junction-free tessellation.
- Swap extractor back-end behind `IExtractor` (no change to solvers).

**Deliverables**: **pure-quad** output with reduced singularities.
**Acceptance**: 100% quads on manifold corpus; **singularity count within ~2–4× of reference
QuadriFlow** on identical inputs; min-cost-flow validated on synthetic graphs with known optima.

---

## P7 — Art direction: features, guides, sizing, symmetry  *(effort: M)* → **M6**

**Tasks**
- `FeatureDetector` (dihedral-angle creases) → orientation constraints + extraction seams.
- `GuideCurve` constraints (stroke tangents pin the field) — the QuadRemesher "guide" feature.
- `SymmetryPlane` (mirror constraints in both solvers; stitch at the plane).
- Finalize `AdaptiveSizing` from curvature.

**Deliverables**: artist controls honored in output.
**Acceptance**: sharp edges preserved as quad edge loops on the hard-surface corpus part; a guide
stroke visibly redirects edge flow; symmetric input → symmetric output; adaptive mode densifies
high-curvature regions.

**Status (in progress):** Note the P6 topology work already gave box & cylinder *correct genus*
(box χ=2, cylinder open tube χ=0, both 100 % quad) — so P7 is now about quality, not correctness.
- ✅ `FeatureDetector` (dihedral creases + open boundaries → per-vertex crease tangent; robust to the
  jagged crease bands a remesher leaves, via a most-opposite-pair tangent).
- ✅ Crease tangents wired into the orientation field as hard pins (`OrientationConstraints`,
  propagated up the hierarchy), on by default (`QuadRemesherOptions.PreserveSharpFeatures`). Box
  improves to **8 irregular (ideal)** and max quad fold 82°→61°; sphere/torus/cylinder unaffected.
- ⏳ Remaining: quad **edges don't yet snap onto the creases** (~57 box quads still straddle an edge,
  folding ≤61°). That needs the QuadriFlow sharp-edge path in the integer solve — `sharp_edges` +
  `allow_changes` (`parametrizer.cpp:36–72`, currently stubbed all-1) and `optimize_positions_sharp` —
  plus ideally a **feature-preserving isotropic remesh** (keep crease lines clean through P2
  relaxation; today the box edges arrive as a jagged sharp band, ~150 false corners). Then
  `GuideCurve`, `SymmetryPlane`, `AdaptiveSizing`.

## P8 — Performance & robustness  *(effort: M)*

**Tasks**
- Per-island parallelism; red-black parallel sweeps tuned; SoA hot-path SIMD (`System.Numerics`).
- **Determinism hardening:** audit every parallel reduction (field energy, area/residual sums) for
  float non-associativity; enforce fixed/sequential or compensated accumulation so output is
  bit-exact for a fixed seed (see [01 — Determinism & parallelism](01-architecture.md#determinism--parallelism)).
- Benchmark harness + perf-regression gate in CI.
- Fuzz/robustness pass over dirty inputs (non-manifold, holes, duplicate verts, zero-area tris);
  defensive degrade everywhere.

**Deliverables**: meets the **< 20 s on 500k–2M tris** target; no crashes on the dirty corpus.
**Acceptance**: perf budget met on reference hardware; robustness corpus passes; deterministic output
for fixed seed.

---

## P9 — Packaging, CLI, API polish  *(effort: S–M)* → **M7 ship**

**Tasks**
- `Quadremesh.Cli` with full option surface + `--help`; progress reporting.
- Public API docs (XML docs + README usage); `IProgress<>`/cancellation.
- NuGet package for `Quadremesh.Core` + `Quadremesh.IO`; semantic versioning.
- Sample gallery (before/after renders from the corpus).

**Deliverables**: installable package + working CLI + docs.
**Acceptance**: `dotnet tool`/NuGet install works clean on Windows+Linux; a new user can remesh an
OBJ from the CLI following the README alone.

## Cross-cutting (every phase)

- Update the **test corpus** and golden files as stages stabilize.
- Validate field/extraction stages against **reference Instant Meshes / QuadriFlow** outputs,
  generated by the offline reference-oracle harness (P0;
  [06 §6.6](../Docs/06-csharp-portability-analysis.md#66-reference-oracle-for-testing-build-im--quadriflow-locally)).
- Keep `Quadremesh.Core` dependency-free and **clean-room** (no code lifted from Nanomesh); no GPL
  code; attribute BSD/MIT influences in NOTICE.
